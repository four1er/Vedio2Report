# Vedio2Report 项目目标

将有字幕的 YouTube 对话视频转为可阅读的中文分章文章。交付物为 GitHub 仓库、公开访问的 Cloudflare Worker 网址，以及说明实现与取舍的 README。

## 验收场景

1. 输入有字幕的 YouTube 链接并发起生成。应用先确认有字幕轨，再创建可恢复的下载任务，缓存非空字幕并向用户标明来源。同一视频的重复请求共用已下载的字幕。已确认没有字幕和暂时无法检查须分别报错，两个场景都不会调用 Gemini。为字幕获取受限的情况准备一份标明来源的固定示例。
2. 使用 Gemini AI Studio API 生成中文文章，按标题、章节和段落排版。生成过程中逐段或逐字渲染到网页，用户能在请求结束前阅读已输出的内容。
3. 支持可选的自然语言要求，让用户约束任务类型、写作风格、目标受众和内容范围。文章忠于字幕。
4. 每个章节标题旁提供 5W1H 查看按钮。章节完成后后台基于完整视频上下文和该章节生成 Who、What、When、Where、Why、How 六个字段，用统一格式展示。
5. 服务端保存本次生成的上下文。浏览器请求章节总结时只提供文章和章节标识。
6. 用 Node.js / TypeScript 开发和测试，在 Cloudflare Workers 上运行。保持模块边界清晰，凭据由服务端管理。
7. README 说明字幕处理、Gemini 流式输出、自然语言要求、章节总结、部署步骤和主要取舍。

## 提升要求

- 主文章支持选填自然语言要求。读者可以限定任务类型、输出风格、目标受众及内容范围，整理发言时遵循这些限制。
- 文章需要按章节组织，正文在生成过程中逐段可读。章末小结自动出现，该章的六字段 5W1H 由后台提前计算。按钮只读取已保存的结果或等待状态。
- 章节正文与一至两句阶段小结在同一次主文章请求中流式到达。某一章写完即开放该章的 5W1H，读者展开时，后续章节继续生成。
- 5W1H 结合完整视频字幕、已经保存的文章和所选章节，接口返回六字段 JSON。前端只发送文章和章节 ID，服务端恢复该次生成的上下文。
- 写作要求留空时，按视频时间顺序覆盖开场、中段与收尾。示例提供发布者标注的 12 个话题时间点，章节时间可以跳转回原片。
- GitHub README 说明字幕获取与处理、Gemini 流式输出、自然语言要求、章节级 5W1H，以及主要工程取舍。[实现说明与运行方法](../README.md)

2026 年 11 月 20 日，在 Chromium 打开公开写作台，通过页面提交视频。为验证后台能力，先让页面不展开任何总结，再从只读接口检查首章是否已准备好，最后点击按钮对照实际六项内容。[在线写作台](https://vedio2report.tf08202000.workers.dev) · [验收脚本](../scripts/verify-deployment.mjs)

| 场景 | 实测结果 |
| --- | --- |
| 指定短片《郭宇的故事③》，写作要求留空 | YouTube 把观看页重定向至 Google 流量验证。字幕预检返回 HTTP 422 和 `SOURCE_UNVERIFIED`，页面显示原因，文章请求为零。随后查询下载任务得到 404。仅凭这次响应无法判断原片是否提供字幕。[原片](https://youtu.be/icpkRA0MC4Q) |
| W3C 无障碍评估短片，写作要求留空 | 使用该片的官方文字稿。15.20 秒看到正文，16.85 秒写完三章，共 22 个正文增量。文字稿不带时间轴，三个章节标题也均未添加时间码。首章未点击就已有六项结果。打开第二章时读到 HTTP 202，面板随后自动显示结果。[原片](https://www.youtube.com/watch?v=C4GIqWeywiI) |
| 安德森访谈，只写两章产品定价问答 | 29.59 秒出现正文，31.55 秒完成两章，共 21 个增量。首章与第二章均在后台生成总结。之后从测试机读取已缓存的两章，分别耗时 56 和 94 毫秒，两个响应都有全部六个字段。 |
| 安德森访谈，写作要求留空，覆盖全片 | 网页先确认该片的 2,801 条存档字幕已就绪。第 13.34 秒出现正文，同一段 Mark 的回答在屏幕上从 24 个字符增长到 62 个。全文用时 6 分 02 秒，收到 323 个正文增量，12 章与发布者时间线逐一对应。10 章有多个子标题，5 章有跨段回答，末章含 4 轮问答。[本次实际生成的对话稿](andreessen-full-interview.md) |

全片验收中，首章在第 15.31 秒写完。先保持面板关闭，从只读接口查到已生成的六项，再点击首章核对。打开第二章时后台尚在运行，面板随后自动填入结果。其余十章的按钮全程未打开，全文完成后逐章查询，12 个响应均为 HTTP 200，且均包含完整六项。

为单独验证“没有字幕”和“可下载”两种结果，workerd 集成测试使用受控的 YouTube 播放器与字幕轨响应。播放器确认无轨时，应用返回 `NO_CAPTIONS`。有轨道时，两次请求共用一个字幕下载任务。测试随后让上游断开，再提交同一视频，新的文章会话仍能使用已下载的字幕。[字幕下载集成测试](../tests/caption-cache-workerd.test.ts)

另一项 workerd 集成测试让 Gemini 总结请求暂时停在上游。浏览器未请求任何总结时，首章后台任务已经启动。在它等待期间，第二章正文照常写完。两个章节的结果随后自动入库。[章节总结集成测试](../tests/workerd.test.ts)
