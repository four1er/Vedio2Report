# Vedio2Report 项目目标

输入任意单个公开 YouTube 视频链接，取得该视频的完整字幕后，按原片顺序将整场实质内容整理为流式呈现的中文分章文章，适用访谈、讲座或操作教程。交付物为 GitHub 仓库、公开访问的 Cloudflare Worker 网址，以及说明实现与取舍的 README。

## 验收场景

1. 输入有字幕的 YouTube 链接并发起生成。应用先确认有字幕轨，再创建可恢复的下载任务，缓存非空字幕并向用户标明来源。同一视频的重复请求共用已下载的字幕。为一个从未缓存的普通链接做验收时，也应从输入链接走完整个流程，并核对读取的是同片字幕。已确认没有字幕和暂时无法检查须分别报错，两个场景都不会调用 Gemini。为字幕获取受限的情况准备一份标明来源的固定示例。
2. 使用 Gemini AI Studio API 阅读从开场到结尾的字幕，按文章标题、主题大章、议题小标题和发言段落排版。默认整理有实质内容的提问、回答、论证和举例，长回答可占多个自然段。生成过程中逐段渲染到网页，读者可在请求结束前读到第一轮问答。
3. 支持可选的自然语言要求，让用户约束任务类型、写作风格、目标受众和内容范围。文章忠于字幕。
4. 每个章节标题旁提供 5W1H 查看按钮。章节完成后后台基于完整视频上下文和该章节生成 Who、What、When、Where、Why、How 六个字段，用统一格式展示。
5. 服务端保存本次生成的上下文。浏览器请求章节总结时只提供文章和章节标识。
6. 用 Node.js / TypeScript 开发和测试，在 Cloudflare Workers 上运行。保持模块边界清晰，凭据由服务端管理。
7. README 说明字幕处理、Gemini 流式输出、自然语言要求、章节总结、部署步骤和主要取舍。

## 提升要求

- 主文章支持选填自然语言要求。读者可以限定任务类型、输出风格、目标受众及内容范围，整理发言时遵循这些限制。
- 默认主文章是可逐段阅读的全片整理稿。相邻的碎句可合并，无信息的口头重复可省略。保留原有的讨论顺序、实质性追问、第一人称回答与关键细节。要求「逐字转写」时才逐段保留口语表达。受众、语气和分章数可单独指定。
- 服务端按来源编号核对已处理范围。连续的几段字幕可对应一段正文，纯填充语可只计入处理进度。验收应同时核对浏览器中的流式显示、全片材料的连续覆盖，以及成稿中开场、中段、收尾的实质内容。
- 每章标题旁都有独立的 5W1H。章正文完成即在后台生成六字段结果，下一章正文继续输出。默认正文和复制稿呈现编辑好的发言与标题。
- 5W1H 结合完整视频字幕、已经保存的文章和所选章节。前端只发送文章和章节 ID 读取六字段 JSON。
- GitHub README 说明字幕获取与处理、Gemini 流式输出、自然语言要求、章节级 5W1H，以及主要工程取舍。[实现说明与运行方法](../README.md)

## 通用链接如何验收

在公开写作台粘贴一个单视频链接并提交。可选取普通视频的 YouTube 字幕轨、带独立 SRT 的发布者视频，以及明确无字幕或无法确认字幕的链接，分别核对下列行为。

| 场景 | 核对项目 |
| --- | --- |
| 读取到 YouTube 字幕 | 来源标记为 `youtube`，每篇文章使用所提交视频的真实字幕。 |
| 读取发布者字幕 | 目录按精确视频 ID 检索，下载时再次核对发布者记录的原片 URL。页面给出可点击的独立字幕出处。3Blue1Brown 目录含 143 条视频记录，正文按需下载。[字幕目录](../src/worker/published-index.json) |
| 启用可选现有字幕服务 | 部署者配置 `SUPADATA_API_KEY` 后，直接读取失败且没有对应发布者记录的视频可使用 `native-api`。验收时应核对实际返回的来源。 |
| 单人视频与多人对谈 | 单人讲解保持讲解，各章依据视频本身确定。对谈的提问和发言归属能在字幕中找到依据。 |
| 确认无字幕或访问受限 | 明确无字幕时报错；遇到流量验证且没有可用来源时显示无法确认。失败条件下网页不提交文章。 |
| 流式正文与章节总结 | 在 HTTP 响应结束前观察到屏幕中的正文增长。字幕处理进度走到片尾，章节写完后后台即准备六个字段，面板可以保持关闭。 |

通过 `--url` 指定任意单片，写作要求留空时验收默认整理稿。传 `--verbatim` 复验逐字模式，传 `--adapted` 复验明确限定范围的写作要求。`--expect-source` 用于校验字幕来源。在线调用受来源可用性影响，实测时需区分发布者字幕、打包存档和直接读取的结果。[验收脚本](../scripts/verify-deployment.mjs)

12 章均通过只读 GET 取得六字段 JSON。网页没有点开首章时，后台就已保存结果。点击标题旁按钮后，固定顺序 Who、What、When、Where、Why、How 的内容与 JSON 逐项相符。第二章首次读取返回 HTTP 202，下一次模拟网关 503，面板随后自动显示真实结果。浏览器请求只含 URL 中的文章和章节 ID，请求体为空。另查已保存的第三章与末章，第三章的 What 是 AI 的商业模式与成本结构，末章的 How 说明受访者如何借助合伙人和投资结果校准判断。

另用相关真实字幕单独复验了编辑尺度。片头的一次试写把「询问和观察是两种方法」加强为「观察是最好的方式」。收紧通用编辑指令后，重新生成片头，成稿保留了两种方法、言行可能不同，以及决策失误的后果。「收入与成本」章的试读保留了每月 200 至 300 美元的定价、企业获得回报的理由和单位成本下降的论证。连续编号能验证处理范围，措辞的强弱仍需对照字幕判断。

全片成稿中，片尾一处没有署名的插话与后续发言曾共用署名。后续回归检查了连续换人、纯寒暄、可确认的同一人继续发言三种情况。此时 Gemini 返回该项目的当日模型请求额度已满，片尾修正只完成了受控响应回归。此后在已部署页面重放前述真实正文流，依次点击 12 个章节标题旁的按钮，12 次无正文 GET 均从线上取得 HTTP 200，面板依序显示六个字段。另一次向量课的指定改写生成两章，第一章已有六项，第二章任务按服务商给出的约 12 小时等待期排队。这次没有取得第二章的新结果。

另检查了指定的郭宇短片。线上字幕预检返回 HTTP 422 和 `SOURCE_UNVERIFIED`，播放器要求登录。此次没有取得可读字幕，测试止于预检。[郭宇短片](https://youtu.be/icpkRA0MC4Q)

### 5W1H 面板遇到中断时

2026 年 11 月 20 日，使用 Chromium 打开公开写作台，重放一篇已有文章的正文，并读取线上保存的章节总结。旧页面在一次模拟的 HTTP 503 后即提示手动重试。更新后，只点一次 5W1H，依次模拟网关返回 503 和连接中断，第三次读取收到真实的 HTTP 200，面板自动显示六项。三次请求都是无正文 GET，收起再展开也直接显示已读结果。另一次读取旧文章得到真实的 HTTP 409，页面解释了该文缺少预生成总结，且没有显示重试按钮。[浏览器端回归测试](../tests/summary-reader.test.ts)

在后台任务测试中，模拟 Gemini 首次返回截断的回答。章节保留等待状态，下一次后台执行成功后即可读取六项。如果连续三轮都截断，接口返回 `SUMMARY_FAILED`，页面仍保留正文和章末小结。[后台任务回归测试](../tests/worker.test.ts)
